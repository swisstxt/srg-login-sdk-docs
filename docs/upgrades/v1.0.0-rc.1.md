# Upgrade to v1.0.0-rc.1

> **Released**: 17 June 2026 · **Stage**: Release Candidate
> **Estimated effort**: ~5 min per app

This is the first **Release Candidate** for 1.0.0 — the entry into the stabilization phase before the stable release. The public API is now **frozen**: rc.1 is functionally identical to beta.13, and this is what 1.0.0 will be, barring critical fixes.

:::info No breaking changes since beta.13
rc.1 introduces **no breaking changes** and **no public API changes** relative to beta.13. If your app already runs on beta.13, upgrading is a one-line version bump. If you are coming from beta.12 or earlier, complete the [beta.13 upgrade guide](/docs/upgrades/v1.0.0-beta.13) first, then bump to rc.1.
:::

## What's new

### 🆕 Android TV / Google TV sample app

rc.1 ships a new sample app demonstrating the **Device Authorization Grant (RFC 8628)** flow on Android TV / Google TV — the login method for input-constrained "10-foot" devices where typing credentials is impractical.

The sample covers the full device-flow lifecycle: login entry, awaiting-activation (user code + verification URI + QR code + countdown), success (UserInfo display), and failure (retry). It is built with Compose + Koin + Material 3 / TV Material, with QR rendering via `qrose`, and complements the existing phone/tablet sample (`androidApp`, Authorization Code Flow + Chrome Custom Tabs).

It also demonstrates the correct consumer wiring for the device flow:

```kotlin
// The device flow requires a device-flow-capable auth context.
// AndroidTvAuthContext is the right type here — AndroidAuthContext is
// WebAuthCapable only and is rejected by DeviceAuthorizationFlow.validateForDeviceFlow.
srgLogin.login(
    loginMethod = LoginMethod.Device,
    authContext = AndroidTvAuthContext(/* application context */),
    additionalScopes = listOf("profile", "email"),
).collect { state ->
    when (state) {
        is LoginState.AwaitingDeviceActivation -> showActivationScreen(
            userCode = state.userCode,
            verificationUri = state.verificationUri,
            verificationUriComplete = state.verificationUriComplete,
            expiresIn = state.expiresIn,
        )
        is LoginState.Success -> onLoggedIn(state.tokenSet)
        else -> { /* Loading / Failure */ }
    }
}
```

Build: `./gradlew :androidTvApp:assembleDebug` (`minSdk = 26`, requires `android.software.leanback`).

## Migration

<Tabs>
  <TabItem value="android" label="Android" default>

Bump the dependency version:

```kotlin
// From:
implementation("ch.srg.login:srglogin-core-android:1.0.0-beta.13")
// To:
implementation("ch.srg.login:srglogin-core-android:1.0.0-rc.1")
```

Maven repository: `https://swisstxt.github.io/srg-login-sdk-distribution-android/`

  </TabItem>
  <TabItem value="android-tv" label="Android TV / Google TV">

Android TV and Google TV consume the **same** Android artifact as phones and tablets — there is no TV-specific package. Apply the same version bump:

```kotlin
// From:
implementation("ch.srg.login:srglogin-core-android:1.0.0-beta.13")
// To:
implementation("ch.srg.login:srglogin-core-android:1.0.0-rc.1")
```

Maven repository: `https://swisstxt.github.io/srg-login-sdk-distribution-android/`

TV apps typically authenticate with the **Device Authorization Grant** (`LoginMethod.Device` + `AndroidTvAuthContext`) — see the new Android TV sample above. The migration itself is just the dependency bump.

  </TabItem>
  <TabItem value="ios" label="iOS">

Update the pinned version in `Package.swift` — use `exact:` for pre-releases:

```swift
.package(
    url: "https://github.com/swisstxt/srg-login-sdk-distribution-apple",
    exact: "1.0.0-rc.1"
)
```

Or in Xcode: File → Add Package Dependencies → set **Exact Version** to `1.0.0-rc.1`.

  </TabItem>
  <TabItem value="tvos" label="tvOS">

tvOS uses the **same** Swift Package as iOS — the distributed XCFramework includes tvOS slices and `Package.swift` declares `.tvOS(.v13)`. Apply the same pinned bump:

```swift
.package(
    url: "https://github.com/swisstxt/srg-login-sdk-distribution-apple",
    exact: "1.0.0-rc.1"
)
```

Or in Xcode: File → Add Package Dependencies → set **Exact Version** to `1.0.0-rc.1`.

  </TabItem>
</Tabs>

If you are upgrading from **beta.12 or earlier**, first follow the [beta.13 upgrade guide](/docs/upgrades/v1.0.0-beta.13) (which contains the breaking changes), then apply the version bump above.

## Per-platform notes

### Android

No configuration changes since beta.13 for phone/tablet integration (`minSdkVersion = 21`, unchanged).

### Android TV / Google TV

Same artifact as Android — no separate package or configuration. The new Android TV sample requires `minSdk = 26` and `android.software.leanback`, but this does not affect your existing phone/tablet integration. TV apps typically authenticate with the Device Authorization Grant.

### iOS

No iOS configuration changes since beta.13. Remember to pin pre-releases with `exact:` rather than `from:`.

### tvOS

Same Swift Package as iOS — the XCFramework ships tvOS slices and `Package.swift` declares `.tvOS(.v13)`. No tvOS-specific configuration; pin with `exact:`.

## What's coming next

The next milestone is the **stable v1.0.0** release. Per our versioning policy, the Release Candidate enters a validation period (minimum one week); if no blocking issue is reported, rc.1 is promoted to 1.0.0 with no further code changes — only the version number changes.

Please validate rc.1 against your app for production readiness and report any issue during the RC window.
