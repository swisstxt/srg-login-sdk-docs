# Upgrade to v1.0.0-rc.2

> **Released**: 18 August 2026 · **Stage**: Release Candidate

rc.2 promotes **Web (browser)** to a first-class platform and lands a set of JWT-signature and browser-lifecycle fixes. For existing **Android / Android TV / iOS / tvOS** apps it is a **drop-in version bump — no breaking changes, no code migration**.

## At a glance

| | |
|---|---|
| ⚠️ Breaking changes | **0** |
| 🔁 Public API changes | None for Android/iOS/tvOS/Android TV (`SrgLogin.completeAuthorization` was made internal, but it was never part of the public API) |
| 🆕 New platform | **Web / JavaScript** — the `SrgLoginWeb` facade, distributed as `@swisstxt/srg-login-sdk` via Git (zero-auth) |
| 🐛 Notable fixes | ES384/ES512 (Android) & ECDSA (iOS) JWT verification now succeed; Custom Tabs no longer require Chrome; login no longer stuck when the browser is dismissed |
| 🎯 Estimated effort per app | ~5 min (version bump from rc.1) |

---

## What's new

### 🆕 Web / JavaScript platform

The SDK now ships a **browser build** — the `SrgLoginWeb` facade, a Promise-based API distributed as `@swisstxt/srg-login-sdk` via Git (zero-auth, `github:…#semver:`). Login is a full-page redirect to the IDP, completed on your callback route with `handleRedirect()`; the typed `UserInfo`, token observation, and SSO helpers mirror the mobile surface.

```typescript
import { SrgLoginWeb } from "@swisstxt/srg-login-sdk";

const sdk = new SrgLoginWeb(/* clientId, redirectUri, "INT", …appIdentity…, postLogoutRedirectUri, enableLogging */);

await sdk.login(["profile", "email", "offline_access"]);   // redirects to the IDP
// …then on your callback route:
const result = await sdk.handleRedirect();
```

See the [Web getting-started guide](/docs/getting-started/web) for the full setup.

:::info For existing mobile apps
This is **additive** — a new platform. It changes nothing for your Android or iOS integration.
:::

### 🐛 EC JWT signatures now verify (Android & iOS)

Previously, EC-signed tokens (ES256 / ES384 / ES512) could be silently rejected on Android (P-384/P-521 encoding bugs, LOGIN-1940) and on iOS (P1363→DER conversion, LOGIN-1969). If your IDP issues EC-signed tokens, rc.2 fixes verification — **no code change required**.

---

## ⚠️ Breaking changes

**None.** rc.2 is a drop-in upgrade from rc.1 for all mobile/TV platforms — same public API, same behaviour. The only visibility change (`SrgLogin.completeAuthorization` → internal, LOGIN-1734) affects a web-lifecycle method that was never part of the public API.

## Stability improvements *(no action required)*

- **ES384 / ES512 JWT verification fixed on Android** — corrected P-384 curve order and P-521 DER length encoding (LOGIN-1940).
- **ECDSA JWT verification fixed on iOS** — P1363→DER conversion before `SecKeyVerifySignature` (LOGIN-1969).
- **Web auth no longer requires Chrome on Android** — Custom Tabs provider resolved dynamically (LOGIN-2016).
- **Login no longer stuck when the browser is dismissed** — lifecycle observer cancels a pending login/logout on return without a redirect (LOGIN-1954).
- **Android & iOS diagnostics routed through `SdkLogger`** instead of `println()` — controllable, categorized, PII-safe (LOGIN-1997 / LOGIN-1970).

## Per-platform notes

### Android

Web authentication now works on devices without Chrome (any Custom Tabs provider, else a plain-browser fallback). ES384/ES512 verification is fixed.

### iOS

ECDSA (ES256/384/512) verification is fixed. No SPM/API changes beyond the version bump.

### tvOS / Android TV

No change — same artifacts as their mobile counterpart, same Device Authorization Grant flow.

### Web *(new)*

Requires a secure context (HTTPS or `localhost`), the Web Crypto API, and Web Storage; tokens are stored in `sessionStorage`. See the [Web getting-started guide](/docs/getting-started/web).
