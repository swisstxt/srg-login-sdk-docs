# Upgrade to v1.0.0-rc.3

> **Released**: 28 September 2026 · **Stage**: Release Candidate

rc.3 makes logout a **real** logout by default and adds browser-less server-side logout types, silent login on the web, and shared OIDC authorization-parameter constants. It carries **two breaking changes** — the no-argument `logout()` now ends the server session, and `ClaimValue` is renamed to `StructuredValue` — both with a small, mechanical migration.

## At a glance

| | |
|---|---|
| ⚠️ Breaking changes | **2** — `logout()` default behaviour (LOGIN-1942); `ClaimValue` → `StructuredValue` rename (LOGIN-2087) |
| 🆕 New features | Browser-less **Silent** & per-device **DeviceOnly** logout · silent login on web · web `additionalParameters` · shared `OidcAuthParams` / `OidcPromptValues` constants · web `logoutLocally()` / `logoutThisDevice()` |
| 🔁 Source compatibility | New `SrgLoginError.InteractionRequired`, `LogoutType.Silent` & `LogoutType.DeviceOnly` variants — exhaustive `when` / `switch` statements must add the new cases |
| 🐛 Notable fixes | Coroutine cancellation is no longer reported as an error (LOGIN-2100) |
| 🎯 Estimated effort per app | ~15 min (dependency bump + logout call-site audit; `+` a mechanical rename if you use structured claims) |

---

## What's new

### 🆕 Browser-less server-side logout — `LogoutType.Silent`

`Silent` ends the session over plain HTTPS with **no browser UI**: RFC 7009 revocation of this device's grant, then OIDC RP-Initiated Logout at `end_session_endpoint`, then the local clear. On iOS it replaces the `FrontChannel` sheet that flashed open and shut on `end_session`. It also gives **tvOS and Android TV a server-side logout for the first time** (they previously had Local + BackChannel only, having no browser for front-channel).

<Tabs>
  <TabItem value="android" label="Android" default>

```kotlin
import ch.srg.login.sdk.auth.LogoutType

// Browser-less: revoke this device's grant + end the SSO session, no UI.
srgLogin.logout(logoutType = LogoutType.Silent())

// Opt out of RFC 7009 revocation (end_session only):
srgLogin.logout(logoutType = LogoutType.Silent(revokeTokens = false))
```

  </TabItem>
  <TabItem value="ios" label="iOS">

```swift
try await srgLogin.logout(logoutType: LogoutType.Silent(revokeTokens: true))
```

  </TabItem>
</Tabs>

:::info Not available on Web
`SrgLoginWeb.logout()` stays a top-level front-channel navigation: in a browser `fetch` resolves redirects itself, so the `Location` header that separates a successful `end_session` from an error page is unreadable. Web logout uses `logout()` / `logoutThisDevice()` / `logoutLocally()` instead.
:::

### 🆕 Per-device logout — `LogoutType.DeviceOnly`

`DeviceOnly` revokes **this device's** grant at the IDP's RFC 7009 `revocation_endpoint` and clears the local session, deliberately **leaving the SSO session intact**. It is the right choice on a TV: with the device-code flow the SSO session belongs to the browser that approved the code, so a full logout from the TV would sign the user out on their phone.

<Tabs>
  <TabItem value="android" label="Android" default>

```kotlin
srgLogin.logout(logoutType = LogoutType.DeviceOnly)
```

  </TabItem>
  <TabItem value="ios" label="iOS">

```swift
try await srgLogin.logout(logoutType: LogoutType.DeviceOnly.shared)
```

  </TabItem>
</Tabs>

### 🆕 Silent login on the web — `SrgLoginWeb.loginSilently()`

Runs the ordinary authorization-code flow with OIDC `prompt=none`, which forbids the IDP from rendering any UI. Use it to **bootstrap from an existing SSO session** this app has not yet claimed (for example after a device-code sign-in completed in the same browser). The expected negative outcome — no reusable session — now surfaces as the typed `SrgLoginError.InteractionRequired`.

```typescript
await sdk.loginSilently(["profile", "email", "offline_access"]);
// …then on your callback route:
const result = await sdk.handleRedirect();
// result.errorCode === "InteractionRequired" → no reusable session; fall back to interactive login.
```

:::warning Guard against redirect loops
A `login_required` answer lands back on your start route. Attempt a silent login **at most once per browser session** (e.g. guard with a `sessionStorage` flag) — an unguarded automatic attempt bounces forever.
:::

### 🆕 Custom authorization parameters + shared constants

The web facade's `login` now accepts an optional `additionalParameters` object to forward arbitrary OIDC/OAuth `/authorize` parameters (LOGIN-2104), closing the parity gap with the mobile API. The well-known parameter **names** and `prompt` **values** are now public constants — `OidcAuthParams` / `OidcPromptValues` (LOGIN-2131) — defined once in the shared core and surfaced on every platform.

<Tabs>
  <TabItem value="android" label="Android" default>

```kotlin
import ch.srg.login.sdk.auth.OidcAuthParams

srgLogin.login(
    loginMethod = LoginMethod.Web,
    authContext = authContext,
    additionalParameters = mapOf(
        OidcAuthParams.UI_LOCALES to "fr",                 // IdP UI language (fr/de/it/rm)
        OidcAuthParams.LOGIN_HINT to "user@example.com",   // pre-fill the account
    ),
)
```

  </TabItem>
  <TabItem value="ios" label="iOS">

```swift
let flow = srgLogin.login(
    loginMethod: LoginMethod.Web.shared,
    authContext: authContext,
    additionalParameters: [
        OidcAuthParams.shared.UI_LOCALES: "fr",
        OidcAuthParams.shared.LOGIN_HINT: "user@example.com",
    ]
)
```

  </TabItem>
  <TabItem value="web" label="Web">

```typescript
import { UI_LOCALES, LOGIN_HINT } from "@swisstxt/srg-login-sdk";

// Kotlin/JS exports top-level constants as { get(): string } — read the key with .get():
await sdk.login(["profile", "email"], {
  [UI_LOCALES.get()]: "fr",
  [LOGIN_HINT.get()]: "user@example.com",
});

// …or pass the literal key strings:
await sdk.login(["profile", "email"], { ui_locales: "fr" });
```

  </TabItem>
</Tabs>

:::info Reserved keys are filtered
Parameters the SDK sets itself (`client_id`, `redirect_uri`, `response_type`, `state`, `nonce`, PKCE, `scope`) are stripped in one tested place, so they cannot be overridden. Only overridable keys have constants. On the web, non-string values are ignored (the wire format is string-only).
:::

### 🆕 Web-only logout entry points — `logoutLocally()` & `logoutThisDevice()`

- **`logoutLocally()`** (LOGIN-2102) — clears this app's session with **no network call and nothing changed at the IDP** (`LogoutType.LocalOnly`). The only web logout that leaves the IDP alone unconditionally, so a later silent login can still pick the session back up.
- **`logoutThisDevice()`** (LOGIN-1942) — revokes this browser's grant and clears the local session (`LogoutType.DeviceOnly`), while `logout()` remains the front-channel navigation that ends the SSO session shared with other apps.

```typescript
await sdk.logoutLocally();      // local clear only, IDP untouched
await sdk.logoutThisDevice();   // revoke this browser's grant (RFC 7009)
await sdk.logout();             // front-channel: ends the SSO session
```

## ⚠️ Breaking changes

Two breaking changes, both with a small migration.

| # | Ticket | Before | After | Action |
|---|---|---|---|---|
| 1 | LOGIN-1942 | `logout()` cleared local tokens only (IDP session stayed alive) | `logout()` defaults to `LogoutType.Silent` — revokes the grant + ends the SSO session over HTTPS | Pass `LogoutType.LocalOnly` explicitly where local-only was intended; handle the new `LogoutResult.Failure` on network error |
| 2 | LOGIN-2087 | `ClaimValue` (type, `when` branches, `Map<String, ClaimValue>`) | `StructuredValue` (identical variants & accessors) | Rename the type; rename `JsonElement.toClaimValue()` → `toStructuredValue()` |

### 1 · `logout()` now ends the server session

Previously the friendliest signature in the API produced a logout that was not one: it cleared local tokens but left the IDP session and refresh token alive, so the next login walked straight back in without credentials. It now attempts both server-side mechanisms (RFC 7009 revocation + `end_session`) before the local clear — still with no browser and no UI.

**Before:**

<Tabs>
  <TabItem value="android" label="Android" default>

```kotlin
srgLogin.logout()   // local-only clear; server session stays alive
```

  </TabItem>
  <TabItem value="ios" label="iOS">

```swift
try await srgLogin.logout()   // local-only clear; server session stays alive
```

  </TabItem>
</Tabs>

**After:**

<Tabs>
  <TabItem value="android" label="Android" default>

```kotlin
// Same call — now a real (browser-less) server logout:
val result = srgLogin.logout()

// Kept the OLD behaviour on purpose (offline logout, fast user switching, teardown)?
srgLogin.logout(logoutType = LogoutType.LocalOnly)

// logout() now performs network I/O and can fail offline — the local session is
// still cleared, so check clearedLocalSession rather than treating Failure as "still logged in":
if (result is LogoutResult.Failure && result.clearedLocalSession) {
    // Local session cleared; the server call did not complete (e.g. offline).
}
```

  </TabItem>
  <TabItem value="ios" label="iOS">

```swift
// Same call — now a real (browser-less) server logout:
let result = try await srgLogin.logout()

// Kept the OLD behaviour on purpose?
try await srgLogin.logout(logoutType: LogoutType.LocalOnly.shared)
```

  </TabItem>
</Tabs>

:::tip Migration tip
Search your codebase for `.logout(` with no `logoutType` argument and decide, per call site, whether you want the new server-side logout (most "Log out" buttons) or the old local-only clear (offline / user-switch / teardown).
:::

### 2 · `ClaimValue` renamed to `StructuredValue`

A **pure rename** — no behaviour change, done before GA (see ADR-017). Variant names (`Null` / `Text` / `Integer` / `Decimal` / `Bool` / `Array` / `Object`) and accessors (`asText`, `asInteger`, …) are unchanged. Only relevant if you read structured claims (`IdTokenClaims.rawClaims`, `UserInfo.rawClaims`, `getObjectClaim` / `getArrayClaim`).

**Before → After:**

<Tabs>
  <TabItem value="android" label="Android" default>

```kotlin
// Before:
val v: ClaimValue = userInfo.rawClaims["address"] ?: ClaimValue.Null
when (v) { is ClaimValue.Text -> v.asText; else -> null }
// After:
val v: StructuredValue = userInfo.rawClaims["address"] ?: StructuredValue.Null
when (v) { is StructuredValue.Text -> v.asText; else -> null }
```

  </TabItem>
  <TabItem value="ios" label="iOS">

```swift
// The SKIE-generated Swift enum is renamed ClaimValue → StructuredValue.
// JS/TS: the exported type name changes accordingly.
```

  </TabItem>
</Tabs>

:::tip Migration tip
Replace `ClaimValue` → `StructuredValue` (types, `when` / `switch` branches, `Map<String, ClaimValue>`), and `JsonElement.toClaimValue()` → `toStructuredValue()` if you use the boundary converter.
:::

### Source-compatibility notes *(additive, but exhaustive matches must be updated)*

These are not API removals, but an **exhaustive** `when` (Kotlin) / `switch onEnum(of:)` (Swift) will no longer compile until you add the new cases:

- **`SrgLoginError.InteractionRequired`** — the four OIDC "cannot answer without UI" errors (`login_required`, `interaction_required`, `consent_required`, `account_selection_required`) now map here instead of `InvalidDataError`. Add a branch (typically: fall back to interactive login).
- **`LogoutType.Silent` and `LogoutType.DeviceOnly`** — an exhaustive Swift `switch onEnum(of: logoutType)` must add `.silent` and `.deviceOnly`. `is` / `as?` checks are unaffected.

## Stability improvements *(no action required)*

- **Coroutine cancellation is no longer reported as an error** (LOGIN-2100) — normal cooperative cancellation of a `login()` / token / OpenID-config network call (e.g. an iOS `AsyncSequence` collector stopping) was caught by broad `catch` blocks and sent to error tracking, or turned into an `SdkResult.Failure`. `CancellationException` is now rethrown first across the network layer, so it always propagates to the collector. A cancelled front-channel logout no longer clears tokens as a side effect; a cancelled refresh no longer leaves `TokenState` stuck on `Refreshing`. No public API change.

## Per-platform notes

### Android

The `logout()` default change applies. Review your logout call sites; `logout()` now performs network I/O. No minSdk or Gradle changes beyond the version bump.

### iOS

`LogoutType.Silent` replaces the front-channel sheet that flashed on `end_session`. Update any exhaustive `switch onEnum(of:)` over `LogoutType` (`.silent`, `.deviceOnly`) and `SrgLoginError` (`.interactionRequired`). The SKIE-generated `ClaimValue` enum is renamed to `StructuredValue`.

### tvOS / Android TV

Device-flow apps gain a server-side logout for the first time: `LogoutType.DeviceOnly` (revoke this device's grant, keep the SSO session — the right choice on TV) and `LogoutType.Silent`. `LocalOnly` and `BackChannel` behaviour is unchanged.

### Web

New: `loginSilently()`, `login(scopes, additionalParameters)`, `logoutLocally()`, `logoutThisDevice()`, and the `OidcAuthParams` / `OidcPromptValues` constants (read exported constants with `.get()`). `logout()` stays a top-level front-channel navigation; `LogoutType.Silent` is intentionally unavailable on web.

## Migration checklist

- [ ] Bump the SDK dependency to `1.0.0-rc.3` (all platforms)
- [ ] Audit `logout()` call sites — keep the new server-side default, or pass `LogoutType.LocalOnly` where local-only was intended
- [ ] Handle `LogoutResult.Failure` from `logout()` on network error (check `clearedLocalSession`)
- [ ] Rename `ClaimValue` → `StructuredValue` (and `toClaimValue()` → `toStructuredValue()`) if you read structured claims
- [ ] Add the new cases to any exhaustive `when` / `switch` over `SrgLoginError` and `LogoutType`
- [ ] (Web, optional) Adopt `loginSilently()` / `additionalParameters`, guarding silent login against redirect loops
- [ ] Smoke-test login, refresh, and logout end-to-end
- [ ] Verify your CI still passes after the dependency bump
